# XIAO白杖とのBLE連携

iPhoneがCentral、XIAOがPeripheralとして動作します。iOS側は `CoreBluetooth` を使用し、設定画面の「白杖 Bluetooth」から検索・機器選択・接続を行います。iOSのBluetooth設定での事前ペアリングは不要です。

## XIAO側に必要な仕様

本書はiOS側が使用するCaneVibeプロトコルv1の仕様です。パケットの実装は `Core/CaneProtocol.swift` を参照してください。XIAOの機種にかかわらず、ファームウェアは次の仕様に合わせてください。

| 項目 | UUID・内容 |
|---|---|
| Advertising service | `77D6F146-E62C-4ED3-BAAA-6C1526D79D28` |
| Command | `BC6B696D-E8D3-4566-9730-EA6B057EE324` / Write with response |
| Status | `D9B72442-A4CC-4E98-9352-CED78C12B22F` / Read + Notify |
| 推奨機器名 | `CaneVibe-01`（接続判定にはUUIDを使用） |

Commandは10バイト、整数はLittle Endianです。

| Offset | 内容 |
|---|---|
| 0 | version=1 |
| 1 | state: 0=検出なし、1=注意、2=危険、3=検知不能 |
| 2–3 | sequence: uint16、65535の次は0 |
| 4–5 | TTL: 1000ms |
| 6–7 | 距離mm: uint16、未知=65535。検出なし・検知不能も65535 |
| 8 | bit0=深度から床を推定、bit1=手動テスト、その他0 |
| 9 | 予約=0 |

Statusも10バイトです。offset 0=version=1、1=採用state、2=error flags（bit0=TTL切れ、bit1=不正パケット）、3=GPIO出力（0/1）、4–5=最後に受理したsequence、6–9=起動後ms（uint32）。各有効Command受理時にNotifyしてください。

FWでは長さ・version・state・TTL・予約ビットを検証し、同一／古いsequenceを受理しないでください。接続ごとにsequence基準を初期化します。最終受理から1000ms経過、または切断時に危険振動を停止し、検知不能へ移行してください。iPhoneからの停止パケットが必ず届く前提にはしません。

XIAO nRF52840 + DRV2605L（LRA/RTP）には、別途配布する対応FW（`CaneVibe.ino` または電源ボタン付きの `CaneVibePower.ino`）が必要です。Seeed nRF52 Boards版で使用します。このiOS変更にはファームウェア本体を含めていません。振動単体テストだけのスケッチではBLE通信できません。

このFWでは危険時は120ms振動を100msの停止を挟んで3回、その後440ms停止（1秒周期）、注意時は300ms振動／1700ms停止（2秒周期）を繰り返します。強度は変えず、単発と3連続のリズムで区別します。検出なし・検知不能・TTL切れ・切断時は停止します。元のGPIO直結案とは異なりGPIO3を駆動しないため、Statusのoffset 3は常に0です。RTP出力値や実際の振動を示す値ではありません。

## アプリの動作

- 対象サービスを広告する機器だけを検索し、選択した機器へ接続。サービス・属性・通知購読を確認してから送信します。
- 接続直後は検知不能を送信。250ms周期で最新状態を再送し、深度フレーム更新時にも送信します。
- 自動送信の距離の既定値は、危険が0.5m以内、注意が0.5m超〜0.8m以内、0.8mより遠い場合は検出なしです（有効な深度がある場合）。連続ブザー距離の保存設定は0.4m以内ですが、現在のアプリではブザー出力を無効化しています。距離判定はiOSで行うため、この変更に伴うXIAOの再書き込みは不要です。
- 自動送信の対象は「頭の高さの障害物」。注意・危険・検出なしを有効深度の同じ状態2フレームで確定します。物体認識や足元の段差の警告は今回の送信対象に含めていません。
- 深度が600msより古い、深度不足、無効姿勢、頭の高さの警告OFF、カメラ停止、カメラ案内以外では検知不能になります。無効入力で連続フレーム数を進めません。
- 音声の再通知間隔とは独立して送信します。Write処理中は次のパケットを積まず、次回に最新状態を再評価します。
- 通信テストは1秒間だけ手動フラグを付けて送信し、検知不能を経由して自動送信に戻ります。
- 検索・接続は15秒、Write応答待ちは2秒、Status受信途絶は3秒でタイムアウトします。切断後は設定から再検索してください。
- バックグラウンド移行時は接続を解除します。再接続は利用者の操作で行います。

## 接続状態の表示

- 設定の「白杖 Bluetooth」で、未接続・検索中・接続中・通信確認中・接続済み・失敗を文字とアイコンで表示します。
- 接続した機器名を表示し、正常なStatusを初めて受信してから「接続済み」にします。通知購読が成功しただけでは完了表示しません。
- 接続完了、接続解除、接続失敗・切断時に5秒間の通知を表示します。通知は閉じるボタンでも消せます。地図・カメラ案内に常時表示する接続バッジはありません。
- 接続完了時はiPhone側の成功フィードバックを1回だけ返し、音声／VoiceOverでも知らせます。Statusを繰り返し受信しても完了通知は繰り返しません。
- 設定画面では接続後に単発／3連続の振動テストが使えます。sequence等の通信詳細はDeveloperModeで表示します。
- UIテストでは未接続画面と地図・カメラに常時バッジがないことを確認します。実機での接続完了通知、切断通知、触覚・音声は別途確認が必要です。

## 実機確認

1. 上記サービスを広告し、Command/StatusとTTL停止を実装したFWをXIAOへ書き込みます。
2. iPhoneでアプリを開き、「設定 → 白杖 Bluetooth → 白杖を検索して接続」を選択。初回はBluetoothを許可します。
3. 検出された機器を選び、「接続済み」とStatusの受信を確認します。
4. 「注意の振動を試す（単発）」「危険の振動を試す（3連続）」を選び、XIAO受信状態・sequence・実際のモーター動作を照合します。受信状態やWrite応答だけでは実振動を証明しません。
5. カメラ案内を開き、頭の高さの障害物への状態遷移を確認します。警告OFF・カメラ停止・深度無効時は検知不能になります。
6. 切断・アプリ背景移行・電波遮断でFWが期限内に危険振動を停止することを確認します。

自動テストはパケット形式、Status復号、フレーム連続判定、鮮度、無効化を検証します。BLE無線通信と実振動は実機で別途確認が必要です。
