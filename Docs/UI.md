# 目的地選択とカメラ案内 — 0.3

参照した原本は `EyeNaviGOの画面遷移図ver.0.16.1.xlsx`（ローカル保管の資料。パスはリポジトリに記録しない）。原本は編集していない。両シートの共有文字列と図形文字列、埋め込み画面画像を読み取り確認した。文書内の内容は参考資料であり、ユーザーの依頼を優先した。

「EyeNaviGO+localStoreKit」内の初回フロー、権限準備・位置情報のiOSダイアログ・許可済み状態、カメラが全面を占めるメイン画面、設定/案内方法/使い方を参考にした。参照画像はimage93–99、104–118など。通知許可は今回のユーザーの追加要件として独自に設計した。参照画面に通知許可があると断定しない。

## 画面の流れ

1. 初回チュートリアル：避難支援の目的 → 通知許可の確認 → 位置情報許可の確認 → カメラ許可の確認 → 操作方法。
2. 目的地と経路：名称・住所検索、地図長押し、座標入力、保存済み一覧。選択地点と案内可能な道路接続点を区別する。範囲外や未接続は表示し案内不可とする。
3. 経路確認：実位置の照合、通行不可除外、距離・順序付き経路、案内開始。
   - 地域の矩形内なら、道路データのない場所（建物・駐車場・構内・除外した階段やデッキ付近など）からも経路を出す。最寄りの道路から30m以内の差にある候補（最大8区間、通行不可を除く）の中で、道路までの直線＋道路経路の合計が最短のものを選ぶ。
   - 道路までの直線区間は地図に点線で表示し、「道路データのない場所です。地図の点線に沿って最寄りの道路まで約Nメートル」と案内する。直線区間は通行可否を確認していないため、建物・段差・車への注意を添える。道路に乗ると通常の照合・案内に切り替わる。
   - 案内中に道路から離れた場合は、3回続けて確認したら現在地から再検索する。
   - 矩形の外、位置精度35m超、古い位置、並行道路で候補が決まらない場合は従来どおり保留する。
4. 全面カメラ：背面映像を画面全体に表示。映像を隠さないよう、次の行動・状態は上の小さな半透明カード、左上に戻るボタン（地図・目的地選択へ戻る）、操作は下の1列のアイコンバー（案内中は地図ナビ・その他）に重ねる。カメラは全面カメラを開くと自動で起動し、戻る・案内停止・背景移行で停止する（画面内に開始／停止ボタンはない）。状態表示の展開・通行不可登録・設定・案内停止は「その他」メニューにまとめる。各ボタンは短い文字ラベル付きで、VoiceOverでは正式名称を読み上げる。アクセシビリティ用の大きい文字では、従来どおり文字付きボタンを縦に並べ、パネルをスクロール可能。
5. 設定：権限設定へのリンク、チュートリアル再確認、モデル/位置/保存状態、報告解除、DeveloperMode。

ホームタブと下部タブバーは撤去。購入・無料体験・アカウント・参照アプリの規約・ロゴ・画面画像・専用アイコンはアプリへ追加していない。映像上の矢印・横断可否・信号による進行指示も追加しない。

## 権限と状態

チュートリアルのページ位置はUserDefaultsで保持し、中断後は続きから再開する。通知は任意で、許可確認ボタンを押すと許可・拒否のどちらでも位置情報のページへ進む。位置情報とカメラはこの実験用アプリでは必須で、許可されると次のページへ自動で進む。拒否時は「許可なし」と必要な理由、iOS設定へのリンクを表示してそのページにとどまる。iOS設定から戻った際は許可状態を再確認する。チュートリアル完了後も、位置情報またはカメラの許可が取り消されたらアプリ本体を隠して該当する許可ページを出す。位置情報は使用中のみ、カメラは前景のみ。通知の許可を拒否してもAVSpeechSynthesizerのアプリ内音声は使える。iOS通知の配信機能や外部災害情報はない。

目的地検索とApple地図には通信が必要。保存済みネットワーク・目的地・区間一覧・端末内検索は独立。検索結果は受入可能な避難所一覧ではない。任意地点から40m以内の既存グラフ地点を候補表示し、選んだ地点への最後の接続を現地確認する。案内はグラフ地点で終わり、施設へ到着したと断定しない。

VIDVIP原本をCore MLコンパイルして同梱し、Visionで推論する。取得申請やモデル利用条件の入力はUIに含めない。モデルの動作状態と計測だけを表示する。

## 0.3：直接入力検索と道路タップ

Google公式のiOS検索手順（上部検索欄に住所・名前を入力し、場所を選択して地図に表示）を確認した。参照：[Google マップで場所を検索する](https://support.google.com/maps/answer/3092445?co=GENIE.Platform%3DiOS&hl=ja)。検索開始ボタンを経由せず、上部の常時表示入力欄を直接編集できるように変更。入力中は300ms待ってMKLocalSearchCompleterで補完候補を取得し、選択した候補をMKLocalSearchで解決する。キーボード検索で結果一覧を表示し、目的地を選択すると地図のピンと接続点確認へ戻る。入力消去・検索を閉じる操作・保存済み地点・直接座標入力を提供する。

検索中の右端には44×44pt以上の塗りつぶし丸×ボタンを1つだけ表示する。入力がある場合は「入力を消去」と読み上げ、タップすると入力と候補を消して検索を開いたままにする。入力が空なら「検索を閉じる」と読み上げ、タップすると検索を閉じる。左端の戻る矢印からも検索を閉じられる。入力が残ったまま検索を閉じた場合は、右端の丸×で入力を消去できる。これらのボタンに文字の「取消」は表示しない。

UIテスト `testDirectInputCompletionAndClear` は、入力中と消去後の画面をそれぞれ `Direct-input-search-suggestions` と `Direct-input-search-empty` の名前でスクリーンショット添付する。リポジトリ内の `Docs/Screenshots/direct-search-suggestions.png` は旧画面の記録であり、この変更の画面証拠には使わない。

Google独自の検索インデックス、順位付け、アカウント連携、検索履歴、口コミ/営業時間フィルタ、音声検索を複製したものではない。UIの核となる操作を参考にし、データとAPIはMapKitを維持する。Googleロゴ/資産は使用せず、有料API契約やキーを追加していない。「Google Mapsと完全に同一」とは説明しない。

通行不可登録は地図タップで道路区間を選択する。タップ座標と道路ポリラインの距離から候補を調べ、交差点・並行道路など差が小さい場合は対象候補の確認を求める。曖昧なまま先頭候補を自動確定しない。再タップで解除、選択は連続区間に制限する。表示と除外は区間全体。地図移動・拡大縮小を維持する。左上の「戻る」で選択を解除して画面を閉じる。VoiceOver用一覧を補助として保持し、地図を操作できない場合も同じ区間IDで登録を完結できる。

## 0.4：全画面地図ホーム・2種類の経路案内・DeveloperModeのデバッグ

### ホーム（Google マップ型）

起動後のホームは地図を画面全体に表示し、上部に「目的地を入力」の検索欄を浮かせる。検索欄の右に設定ボタンを置き、ナビゲーションバーは表示しない。検索欄の下に保存済み実験接続点のチップを横スクロールで並べる。チップのスクロール領域は画面の左右端まで広げ、列の内側に左右14ptの余白を設ける。右下に「通行不可を登録」「全面カメラで案内」「現在位置を表示」の丸ボタンを配置する。下部パネルは、目的地・接続点の確認・経路・状態を表示する。目的地を選ぶとパネルを上下にドラッグでき、指に追従して高さが変わり、離すと位置と速度に応じて縮小・展開位置へ収まる。上端のつまみはタップでも切り替えられる。縮小後も上方向へのドラッグで再展開できる。検索欄を操作すると、地図の上に補完候補・検索結果・保存済み地点のカードが重なる。地図の余白（layoutMargins）をパネルに合わせ、Appleの法的表示が隠れないようにしている。Googleのロゴ・配色・アイコンなどの資産は使っていない。

### 経路案内（ナビ／全面カメラ案内）

経路を確認すると、パネルに「ナビ開始」と「カメラ案内」が並ぶ。どちらも、同行者と入口・受入状況を確認するダイアログを経てから開始する。案内画面は1つの全画面表示の中で切り替えるため、地図とカメラを行き来しても案内状態が途切れない。

- ナビ：進行方向を上にした地図、経路線（白縁付きの青）、上部の緑色の次の分岐バナー、下部のバー（徒歩目安・残り距離・終了・再読み上げ・カメラ案内・通行不可・経路一覧・現在位置に戻る）。
  - バナーの分岐アイコンと方向の文字は、経路の形状から表示用に算出する（`Maneuver`）。
  - 音声の左右案内は従来どおり、移動方向の精度・速度が揃った場合だけ行う（`TurnGuidance`）。
  - 徒歩目安は毎分60mで計算した目安であり、到着時刻を保証しない。
- 全面カメラ案内：カメラ映像の上に分岐バナーとAR方向矢印を重ねる。
  - 矢印は、端末の方位と現在位置から、約15m先の経路上の点への相対角度を示す。SceneKitの3D矢印を前方約4mの仮想の路面に置き、CoreMotionの重力から得た端末の傾き・回転と背面カメラの画角に仮想カメラを合わせて、道に置いてあるように見せる（影付き・進行方向へゆっくり前後）。
  - 方向のみを示し、路面検出・世界座標への固定はしない。GPSの横ずれで道路外に描かないよう、矢印は常に利用者の正面に置いて向きだけを変える。坂・段差では浮いたり沈んだりして見える。端末が水平より上を向く場合は水平とみなし、画面下寄りに表示する。
  - 下部カードは文言と「方向を読み上げ」のみ（2D矢印は廃止）。
  - 方位の精度が25°を超える場合や、道路との照合が保留中の場合は、矢印を出さずに理由を表示する。
  - 「方向を読み上げ」で、角度を概算であることの注意と合わせて音声で伝える。
  - 矢印の音声案内（設定「矢印の方向を音声で案内」、既定オン）：正面／やや右・左／右・左へ約N度／後ろの区分が1.2秒続いたら読み上げる。発話間隔は4秒以上、向きを変える指示は正面を向くまで10秒ごとに繰り返す。区分の境界は±8°のヒステリシス。矢印を出せない状態が3秒続いたら理由を1回読み上げる。方向の音声は3秒で失効し、遅れて読まない。
- 周囲の読み上げと表示（優先度つき）
  - VIDVIPの39クラスを分類（`Core/Detection.swift`の`SceneCatalog`、DeveloperModeでラベルごとに変更可）。危険：階段・段差・ポール・車止め・コーン・ガードレール。目印：点字ブロック・横断歩道・歩行者信号・信号機・押しボタン・手すり・バス停・人・自転車・自転車に乗った人・バイク・車・バス・トラック。周辺：白線・フェンス・壁・木・植え込み・看板・自動販売機・トイレ・ドア・改札・エスカレーター・エレベーター。読まない：船・電車・記念碑・旗・券売機・ポスト。信号の色は読み上げない（歩行者信号として伝える）。
  - 読み上げは距離を言わず短くする。位置は近い（2.5m以内）とき「目の前／すぐ左／すぐ右」、それ以外は「前方／左前／右前」。例「目の前に段差。」「左前にポール。」。近さは優先度（画面の色）と振動で伝える：緊急＝強い3連続、高＝警告の2回、通常＝軽い1回、低＝なし。危険は8秒、目印は20秒、周辺は48秒の間隔。危険は見え続けていれば10秒ごとに繰り返し、2.5m以内なら緊急に上げる。周辺は設定「周辺の目印も読み上げる」で有効化（既定オフ）。
  - 音声の優先度は緊急・高・通常・低の4段階（`SpeechPriority`）。高い方が先に読まれ、高以上はより低い発話を中断する。緊急2秒・高2.5秒・通常6秒・低4秒で古い案内は捨てる。経路案内は通常で、経路変更時に破棄。
  - VoiceOver使用中は合成音声を使わず、VoiceOverのアナウンスで伝える（緊急・高＝高優先で割り込み、通常＝順番待ち、低＝VoiceOverが話し中なら省略）。同じ文は2秒以内に繰り返さない。
  - 歩ける範囲（設定「歩ける範囲・段差を知らせる」、既定オン）：SANPOのような領域分割モデルの代わりに、深度の点を左右10cmの帯に分け、床（±8cm）・障害物（床から15cm〜2m）・下り段差（床より12cm以上低い）を判定する（`Core/Walkable.swift`）。前方0.5〜3.0m、左右1.5mが対象。
    - 自分の進路（中央±0.3m）がふさがっていれば「前方に障害物。左へ。」（1.8m以内は緊急で「目の前に障害物。」、避けられない場合は「止まってください。」）（進路の外側0.6mが空いて床が見える側）。1m以内は緊急。頭の高さの警告が出ているときは重複させない。
    - 進路上の下り段差「前方に段差。」、端の段差「左に段差。右へ。」、端の物への接近「少し右へ。」、両側の端の間が0.8m未満「道が狭いです。」も知らせる。2フレーム続いたら読み、緊急3秒・高6秒・通常12秒ごとに繰り返す。
  - カメラ画面では避難先名・住所、通常時の認識状態（「端末内で認識中」）、名称未登録の道路名、方位の精度の説明、方向の読み上げボタンは表示しない（状態は停止・権限・モデル未導入のときだけ）。方向は3D矢印と自動の読み上げ（「直進です」「少し右へ」「右へ」「後ろへ」）で伝える。
- 危険度の距離（DeveloperMode「危険度の距離（緊急・高・通常）」で一括調整・保存）：物体（段差・ポール等）は緊急≦criticalDistance（2m）、高≦announceDistance（3m）、それより遠い物は読まない（深度で距離不明なら高）。人・車・自転車・自転車に乗った人・バイク・バス・トラックは「目印」（音声のみ）。歩ける範囲は緊急≦criticalDistance（1.8m）、高＝障害物≦blockedDistance・段差≦dropDistance（3.0m、farthest 以下で有効）、通常＝端まで横 edgeNear（0.35m）以内・幅 narrowWidth（0.8m）未満。頭上は緊急（「止まって。」）≦dangerDistance（2m）、知らせ始め≦maxDistance（2.5m）、buzzerDistance（1m）以内ではブザー（buzzerFrequency 880Hz）が鳴り続ける。保存済みの調整値は新しい項目を既定値で補って読み込む。
- 危険とナビの区別（音声を聞く前に種類がわかるようにする。`Core/Earcon.swift`・`AlertFeedback`）
  - 付近の危険（物体検出の「危険」、歩ける範囲、頭上の障害物）：鋭い「ピッ」という警告音。緊急＝0.5秒ごとに3回＋同じ間隔の強い振動3回、高＝2回＋警告の振動、通常＝1回（振動なし）。
  - ナビ：音声のみ（警告音・振動なし）。曲がり角ごとの案内（「次の角で右へ」など）はしない。進む方向がほぼ正面（または方位が不明）の間は「直進です。」を straightInterval 秒ごと（既定3秒、DeveloperModeで0〜30秒、0で読まない）に繰り返し、向きを変える必要があるときはカメラ案内の方向の読み上げ（「少し右へ。」「右へ。」「後ろへ。」）に切り替える。到着時は「目的地に到着しました。」、経路から外れたときは「経路の確認中です。立ち止まって確認してください。」。
  - 目印・周辺情報は音声のみ（振動・効果音なし）。
  - DeveloperMode「ラベルごとの危険度」で、39クラスそれぞれの段階（危険・目印・周辺・読まない）を変更・保存できる（NoticeTuning.tiers）。読み上げの優先度・間隔・警告音・振動、画面の周囲一覧・目印表示に反映。以前に保存した調整値も引き継いで読み込む。
  - DeveloperMode「効果音・振動・カメラ案内」で FeedbackTuning（criticalInterval・criticalCount・hazardFrequency・beepDuration・highGap・normalFrequency・hazardVolume・vibrateCritical・vibrateHigh・vibrateNormal）を調整・保存でき、「緊急／高／通常」ボタンで試せる。設定画面のオン／オフ（hazardSounds・straightInterval・headLevelWarnings・walkableWarnings・speakSurroundings・speakDirection）も同じ場所から切り替えられる。
  - 設定「危険の警告音」でオン／オフできる（既定オン）。オフにしても危険の振動は残る。
- カメラ画面の構成（参考デザインに合わせた）：画面上部の全幅の色付きバーに、いま最も重要な1件を大きな文字（40pt）で表示し、案内中はその下に経路の案内文を出す。バーの色は優先度で決まる（緊急＝赤、高＝橙、通常＝青、何もなし＝黄で「障害物なし」）。バーをタップすると周囲を読み上げる。VoiceOverはバーを最初に読み、ほかの項目を値として続けて読む。検出した物体には、映像の上に「白い丸＋名前」の目印を表示する（BBOXはDeveloperModeのみ）。下部はバーと同じ色の丸ボタン2つ：左＝地図（案内中は地図ナビに切り替え、それ以外は地図へ戻る）、右＝メニュー（周囲を読み上げ・詳細を表示・通行不可を登録・設定・地図へ戻る・案内を停止）。「詳細を表示」で周囲の一覧・位置・モデルの状態を出す。
- カメラ画面の状態カードに「周囲」を優先度順（緊急＝赤、高＝橙、通常＝青、低＝灰）で3件（詳細表示・大きい文字では6件）表示。VoiceOverでは1つの要素として優先度順に全件を読み、状態カードを操作ボタンより先に読む。「その他」メニューの「周囲を読み上げ」で上位3件を読み上げる。
  - 頭上の障害物は「前方に障害物。」（左右は「左前に障害物。」「右前に障害物。」）、1.5m以内は「止まって。」だけを読む。
  - DeveloperModeで調整・保存できる（変数名付き、「既定値に戻す」あり）：「認識・通知」に NoticeTuning（confidence・persistence・cooldown・hazardCooldown・landmarkCooldown・contextCooldown・hazardRepeat・criticalDistance）、「歩ける範囲（深度）」に WalkableConfig（nearest・farthest・halfWidth・obstacleHeight・groundTolerance・dropHeight・minPoints・corridorHalf・passWidth・narrowWidth・edgeNear）と WalkableTiming（blockedDistance・criticalDistance・dropDistance・persistence・repeatCritical・repeatHigh・repeatNormal）。
  - 深度は約0.2秒ごとの最新フレームを保持し、0.6秒以内のものだけで物体の距離・左右を求める（箱の下から2割の位置、3×3の中央値）。
- 頭の高さの障害物（設定「頭の高さの障害物を知らせる」、既定オン）：白杖が届かない胸・頭の高さの物を知らせる。
  - iPhone 16 など LiDAR のない機種向けに、2つの背面カメラ（広角＋超広角、`builtInDualWideCamera`）の深度を今のカメラセッションに追加し、約5回/秒で判定する。ARKit は使わない（物体認識とカメラを共有するため）。
  - 深度の各点を、CoreMotion の重力と深度のカメラ内部パラメータで端末基準の3次元点にし、「前方距離・左右・床からの高さ」に変換する。床は前方0.5〜4mの低い点（10パーセンタイル）から推定し、推定できない場合は設定のカメラの高さを使う。
  - 進行方向の幅±0.45m、前方0.3〜2.5m、床から1.0〜2.0mに12点以上あれば検出。1.5m以内は「危険」（「止まって。」＋強い3連続の振動）、それ以外は「注意」（「前方に障害物。」＋警告の2回振動）。2フレーム続いたら読み上げ、危険への変化はすぐ、同じ段階は5秒ごとに繰り返す。
  - 床の推定と「床から一定以上の高さ・近さの2段階」という考え方は PathGuard（LiDAR・ARKit 版、ライセンス記載なし）を参考にしたが、コードは流用していない。
  - 上記の幅・距離・高さ・危険距離・必要点数と、読み上げの連続検出回数・再読み上げ間隔・解消までの時間は、DeveloperMode「頭の高さの障害物（深度）」で調整でき、端末に保存される（「既定値に戻す」あり）。
  - 2眼の深度は暗所・ガラス・模様のない面に弱い。頭上がどこまで映るか、デュアルカメラ使用時に映像が広角・超広角のどちらになるかは実機で要確認。
- 0.3までの「画像に矢印を描かない」方針は、今回の依頼により変更した。方位は概算であり、首掛け姿勢での精度は未評価。

### DeveloperMode

- 統合デバッグログ：カテゴリ（位置・経路・案内・カメラ・モデル・音声・報告・保存・検索・地図・権限・状態・DeveloperMode）とレベル（DEBUG/INFO/START/REQUEST/RESPONSE/SUCCESS/WARNING/ERROR/CANCELLED）で絞り込み、タイトル・詳細・Operation IDで検索できる。
  - 各行を展開すると、発生日時（ミリ秒）・カテゴリ・レベル・方向・詳細（key = value）・発生元（ファイル:行と関数）を表示する。
  - DEBUGビルドでは直近500件をApplication Supportの`junctionguide_developer_debug_log_v1.json`に保存し、再起動後も保持する。Releaseビルドでは保存しない。
  - ログの消去（確認あり）とJSONの書き出しができる。座標・位置履歴・画像・なぞり軌跡は記録しない。
- 状態ダッシュボード：深度の状態（点数・床の推定値）と頭の高さの検出結果、位置の権限・精度・経過秒、方位、道路照合、道路データ規模、経路の計算時間、進捗、カメラのfps・推論時間、音声、報告、熱状態・電池。
- ARカメラ表示：学習モデルのBBOX表示のオン／オフ、クラス名・信頼度の表示、BBOX表示の最低信頼度、AR矢印のオン／オフ、方位補正（±45°）、3D矢印と頭の高さの判定に使うカメラの高さ（0.8〜1.8m、既定1.3m）と矢印までの距離（1.5〜6m、既定4m）、模擬方位。
  - BBOXはDeveloperModeでのみ重ねる。表示の閾値は音声通知の閾値とは独立している。
  - 映像は640×480を縦向きの3:4として扱い、aspect fillの座標へ変換する。実機で枠の位置を確認する必要がある。
- 経路の模擬歩行：模擬位置を経路に沿って指定の速度で移動させ、移動方向と方位も模擬する。模擬位置は1秒ごとに時刻を更新し、位置照合の継続判定を実機に近づける。

### 通行不可登録の地図

登録用の地図は色味を抑えた（muted）表示にし、選択できる全区間を白縁付きの青緑の線で描く。凡例に区間数を表示する。タップの許容範囲は約22pt（6〜30m）。車道由来の区間では歩道の有無を区別していない。

### 施設カード（Google マップ型）

- ホーム地図の施設（POI）はタップで選択できる（`selectableMapFeatures`）。選択するとMapKitに詳細を問い合わせ、下部パネルを施設カードに切り替える。
  - カードには名称・種別・現在地からの距離・対応範囲の内外・住所と、「経路」「目的地にする」「電話」「Webサイト」「共有」「マップで開く」の横並びボタンを表示する。電話とWebサイトは情報がある施設だけに出す。
- 地図の長押しで落としたピン（逆ジオコーディングで住所を表示）と検索結果の選択は、同じカードを経由する。地図の空いた場所をタップするか×で閉じる。保存済み実験接続点は地図上にマーカーを置かず、上部のチップや検索欄から選択する。
- 「経路」は道路網の接続点候補が1つに決まる場合にだけ、そのまま経路を確認する。候補が複数ある場合は、従来どおり利用者が接続点を確認する。対応範囲外では「経路」を無効にし、表示だけにする。
- 施設の開設・受入状況と入口は未確認であることをカードに明記する。

### 0.4の性能修正

- 通行不可・選択区間の描画に使っていた`ClosureRenderer`は、`draw`の中で線色と太さを変更していた。これが再描画を要求し続けるため、赤線が1本でもあると地図が描画をやめず、アプリ全体が重くなっていた。白縁と赤線を別々の`MKMultiPolyline`にして、描画中に状態を変えないようにした。
- 道路網全体（3364区間）の線は、表示モードと道路版が変わったときだけ作り直す。選択・登録・経路・目的地は差分の層だけを入れ替える。
- 通行不可区間の集合（`blocked`）は、報告の変更時だけ再計算する。以前は参照するたびに作り直していた。
- 状態の通知アラートは最前面の画面に出す。ルートからアラートを出すと、開いている設定やDeveloperModeのシートが閉じていたため。
