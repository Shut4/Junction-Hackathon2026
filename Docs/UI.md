# 避難先選択とカメラ案内 — 0.3

参照した原本は `EyeNaviGOの画面遷移図ver.0.16.1.xlsx`（ローカル保管の資料。パスはリポジトリに記録しない）。原本は編集していない。両シートの共有文字列と図形文字列、埋め込み画面画像を読み取り確認した。文書内の内容は参考資料であり、ユーザーの依頼を優先した。

「EyeNaviGO+localStoreKit」内の初回フロー、権限準備・位置情報のiOSダイアログ・許可済み状態、カメラが全面を占めるメイン画面、設定/案内方法/使い方を参考にした。参照画像はimage93–99、104–118など。通知許可は今回のユーザーの追加要件として独自に設計した。参照画面に通知許可があると断定しない。

## 画面の流れ

1. 初回チュートリアル：避難支援の目的 → 通知許可の確認 → 位置情報許可の確認 → カメラ許可の確認 → 操作方法。
2. 避難先と経路：名称・住所検索、地図長押し、座標入力、保存済み一覧。選択地点と案内可能な道路接続点を区別する。範囲外や未接続は表示し案内不可とする。
3. 経路確認：実位置の照合、通行不可除外、距離・順序付き経路、案内開始。
   - 地域の矩形内なら、道路データのない場所（建物・駐車場・構内・除外した階段やデッキ付近など）からも経路を出す。最寄りの道路から30m以内の差にある候補（最大8区間、通行不可を除く）の中で、道路までの直線＋道路経路の合計が最短のものを選ぶ。
   - 道路までの直線区間は地図に点線で表示し、「道路データのない場所です。地図の点線に沿って最寄りの道路まで約Nメートル」と案内する。直線区間は通行可否を確認していないため、建物・段差・車への注意を添える。道路に乗ると通常の照合・案内に切り替わる。
   - 案内中に道路から離れた場合は、3回続けて確認したら現在地から再検索する。
   - 矩形の外、位置精度35m超、古い位置、並行道路で候補が決まらない場合は従来どおり保留する。
4. 全面カメラ：背面映像を画面全体に表示。映像を隠さないよう、次の行動・状態は上の小さな半透明カード、左上に戻るボタン（地図・避難先選択へ戻る）、操作は下の1列のアイコンバー（案内中は地図ナビ・その他）に重ねる。カメラは全面カメラを開くと自動で起動し、戻る・案内停止・背景移行で停止する（画面内に開始／停止ボタンはない）。状態表示の展開・通行不可登録・設定・案内停止は「その他」メニューにまとめる。各ボタンは短い文字ラベル付きで、VoiceOverでは正式名称を読み上げる。アクセシビリティ用の大きい文字では、従来どおり文字付きボタンを縦に並べ、パネルをスクロール可能。
5. 設定：権限設定へのリンク、チュートリアル再確認、モデル/位置/保存状態、報告解除、DeveloperMode。

ホームタブと下部タブバーは撤去。購入・無料体験・アカウント・参照アプリの規約・ロゴ・画面画像・専用アイコンはアプリへ追加していない。映像上の矢印・横断可否・信号による進行指示も追加しない。

## 権限と状態

チュートリアルのページ位置はUserDefaultsで保持し、中断後は続きから再開する。通知は任意で、許可確認ボタンを押すと許可・拒否のどちらでも位置情報のページへ進む。位置情報とカメラはこの実験用アプリでは必須で、許可されると次のページへ自動で進む。拒否時は「許可なし」と必要な理由、iOS設定へのリンクを表示してそのページにとどまる。iOS設定から戻った際は許可状態を再確認する。チュートリアル完了後も、位置情報またはカメラの許可が取り消されたらアプリ本体を隠して該当する許可ページを出す。位置情報は使用中のみ、カメラは前景のみ。通知の許可を拒否してもAVSpeechSynthesizerのアプリ内音声は使える。iOS通知の配信機能や外部災害情報はない。

目的地検索とApple地図には通信が必要。保存済みネットワーク・目的地・区間一覧・端末内検索は独立。検索結果は受入可能な避難所一覧ではない。任意地点から40m以内の既存グラフ地点を候補表示し、選んだ地点への最後の接続を現地確認する。案内はグラフ地点で終わり、施設へ到着したと断定しない。

VIDVIP原本をCore MLコンパイルして同梱し、Visionで推論する。取得申請やモデル利用条件の入力はUIに含めない。モデルの動作状態と計測だけを表示する。

## 0.3：直接入力検索と道路タップ

Google公式のiOS検索手順（上部検索欄に住所・名前を入力し、場所を選択して地図に表示）を確認した。参照：[Google マップで場所を検索する](https://support.google.com/maps/answer/3092445?co=GENIE.Platform%3DiOS&hl=ja)。検索開始ボタンを経由せず、上部の常時表示入力欄を直接編集できるように変更。入力中は300ms待ってMKLocalSearchCompleterで補完候補を取得し、選択した候補をMKLocalSearchで解決する。キーボード検索で結果一覧を表示し、目的地を選択すると地図のピンと接続点確認へ戻る。入力消去・検索を閉じる操作・保存済み地点・直接座標入力を提供する。

検索中の右端には44×44pt以上の塗りつぶし丸×ボタンを1つだけ表示する。入力がある場合は「入力を消去」と読み上げ、タップすると入力と候補を消して検索を開いたままにする。入力が空なら「検索を閉じる」と読み上げ、タップすると検索を閉じる。左端の戻る矢印からも検索を閉じられる。入力が残ったまま検索を閉じた場合は、右端の丸×で入力を消去できる。これらのボタンに文字の「取消」は表示しない。

UIテスト `testDirectInputCompletionAndClear` は、入力中と消去後の画面をそれぞれ `Direct-input-search-suggestions` と `Direct-input-search-empty` の名前でスクリーンショット添付する。リポジトリ内の `Docs/Screenshots/direct-search-suggestions.png` は旧画面の記録であり、この変更の画面証拠には使わない。

Google独自の検索インデックス、順位付け、アカウント連携、検索履歴、口コミ/営業時間フィルタ、音声検索を複製したものではない。UIの核となる操作を参考にし、データとAPIはMapKitを維持する。Googleロゴ/資産は使用せず、有料API契約やキーを追加していない。「Google Mapsと完全に同一」とは説明しない。

通行不可登録は地図タップが初期表示。タップ座標と道路ポリラインの距離から候補を調べ、交差点・並行道路など差が小さい場合は対象候補の確認を求める。曖昧なまま先頭候補を自動確定しない。再タップで解除、選択は連続区間に制限する。表示と除外は区間全体。地図移動・拡大縮小を維持し、なぞり操作は詳細操作に分離。VoiceOver用一覧を補助として保持し、地図を操作できない場合も同じ区間IDで登録を完結できる。

## 0.4：全画面地図ホーム・2種類の経路案内・DeveloperModeのデバッグ

### ホーム（Google マップ型）

起動後のホームは地図を画面全体に表示し、上部に「目的地を入力」の検索欄を浮かせる。検索欄の右に設定ボタンを置き、ナビゲーションバーは表示しない。検索欄の下に保存済み実験接続点のチップを横スクロールで並べる。チップのスクロール領域は画面の左右端まで広げ、列の内側に左右14ptの余白を設ける。右下に「通行不可を登録」「全面カメラで案内」「現在位置を表示」の丸ボタンを配置する。下部パネルは、避難先・接続点の確認・経路・状態を表示し、上端のつまみで展開と縮小を切り替える。検索欄を操作すると、地図の上に補完候補・検索結果・保存済み地点のカードが重なる。地図の余白（layoutMargins）をパネルに合わせ、Appleの法的表示が隠れないようにしている。Googleのロゴ・配色・アイコンなどの資産は使っていない。

### 経路案内（ナビ／全面カメラ案内）

経路を確認すると、パネルに「ナビ開始」と「カメラ案内」が並ぶ。どちらも、同行者と入口・受入状況を確認するダイアログを経てから開始する。案内画面は1つの全画面表示の中で切り替えるため、地図とカメラを行き来しても案内状態が途切れない。

- ナビ：進行方向を上にした地図、経路線（白縁付きの青）、上部の緑色の次の分岐バナー、下部のバー（徒歩目安・残り距離・終了・再読み上げ・カメラ案内・通行不可・経路一覧・現在位置に戻る）。
  - バナーの分岐アイコンと方向の文字は、経路の形状から表示用に算出する（`Maneuver`）。
  - 音声の左右案内は従来どおり、移動方向の精度・速度が揃った場合だけ行う（`TurnGuidance`）。
  - 徒歩目安は毎分60mで計算した目安であり、到着時刻を保証しない。
- 全面カメラ案内：カメラ映像の上に分岐バナーとAR方向矢印を重ねる。
  - 矢印は、端末の方位と現在位置から、約15m先の経路上の点への相対角度を示す。SceneKitの3D矢印を前方約4mの仮想の路面に置き、CoreMotionの重力から得た端末の傾き・回転と背面カメラの画角に仮想カメラを合わせて、道に置いてあるように見せる（影付き・進行方向へゆっくり前後）。
  - 方向のみを示し、路面検出・世界座標への固定はしない。GPSの横ずれで道路外に描かないよう、矢印は常に利用者の正面に置いて向きだけを変える。坂・段差では浮いたり沈んだりして見える。端末が水平より上を向く場合は水平とみなし、画面下寄りに表示する。
  - 下部カードは文言と「方向を読み上げ」のみ（2D矢印は廃止）。
  - 方位の精度が25°を超える場合や、道路との照合が保留中の場合は、矢印を出さずに理由を表示する。
  - 「方向を読み上げ」で、角度を概算であることの注意と合わせて音声で伝える。
  - 矢印の音声案内（設定「矢印の方向を音声で案内」、既定オン）：正面／やや右・左／右・左へ約N度／後ろの区分が1.2秒続いたら読み上げる。発話間隔は4秒以上、向きを変える指示は正面を向くまで10秒ごとに繰り返す。区分の境界は±8°のヒステリシス。矢印を出せない状態が3秒続いたら理由を1回読み上げる。方向の音声は3秒で失効し、遅れて読まない。
- 0.3までの「画像に矢印を描かない」方針は、今回の依頼により変更した。方位は概算であり、首掛け姿勢での精度は未評価。

### DeveloperMode

- 統合デバッグログ：カテゴリ（位置・経路・案内・カメラ・モデル・音声・報告・保存・検索・地図・権限・状態・DeveloperMode）とレベル（DEBUG/INFO/START/REQUEST/RESPONSE/SUCCESS/WARNING/ERROR/CANCELLED）で絞り込み、タイトル・詳細・Operation IDで検索できる。
  - 各行を展開すると、発生日時（ミリ秒）・カテゴリ・レベル・方向・詳細（key = value）・発生元（ファイル:行と関数）を表示する。
  - DEBUGビルドでは直近500件をApplication Supportの`junctionguide_developer_debug_log_v1.json`に保存し、再起動後も保持する。Releaseビルドでは保存しない。
  - ログの消去（確認あり）とJSONの書き出しができる。座標・位置履歴・画像・なぞり軌跡は記録しない。
- 状態ダッシュボード：位置の権限・精度・経過秒、方位、道路照合、道路データ規模、経路の計算時間、進捗、カメラのfps・推論時間、音声、報告、熱状態・電池。
- ARカメラ表示：学習モデルのBBOX表示のオン／オフ、クラス名・信頼度の表示、BBOX表示の最低信頼度、AR矢印のオン／オフ、方位補正（±45°）、3D矢印のカメラの高さ（0.8〜1.8m、既定1.3m）と矢印までの距離（1.5〜6m、既定4m）、模擬方位。
  - BBOXはDeveloperModeでのみ重ねる。表示の閾値は音声通知の閾値とは独立している。
  - 映像は640×480を縦向きの3:4として扱い、aspect fillの座標へ変換する。実機で枠の位置を確認する必要がある。
- 経路の模擬歩行：模擬位置を経路に沿って指定の速度で移動させ、移動方向と方位も模擬する。模擬位置は1秒ごとに時刻を更新し、位置照合の継続判定を実機に近づける。

### 通行不可登録の地図

登録用の地図は色味を抑えた（muted）表示にし、選択できる全区間を白縁付きの青緑の線で描く。凡例に区間数を表示する。タップの許容範囲は約22pt（6〜30m）。車道由来の区間では歩道の有無を区別していない。

### 施設カード（Google マップ型）

- ホーム地図の施設（POI）はタップで選択できる（`selectableMapFeatures`）。選択するとMapKitに詳細を問い合わせ、下部パネルを施設カードに切り替える。
  - カードには名称・種別・現在地からの距離・対応範囲の内外・住所と、「経路」「目的地にする」「電話」「Webサイト」「共有」「マップで開く」の横並びボタンを表示する。電話とWebサイトは情報がある施設だけに出す。
- 保存済み地点のピン、地図の長押しで落としたピン（逆ジオコーディングで住所を表示）、検索結果の選択も、同じカードを経由する。地図の空いた場所をタップするか×で閉じる。
- 「経路」は道路網の接続点候補が1つに決まる場合にだけ、そのまま経路を確認する。候補が複数ある場合は、従来どおり利用者が接続点を確認する。対応範囲外では「経路」を無効にし、表示だけにする。
- 施設の開設・受入状況と入口は未確認であることをカードに明記する。

### 0.4の性能修正

- 通行不可・選択区間の描画に使っていた`ClosureRenderer`は、`draw`の中で線色と太さを変更していた。これが再描画を要求し続けるため、赤線が1本でもあると地図が描画をやめず、アプリ全体が重くなっていた。白縁と赤線を別々の`MKMultiPolyline`にして、描画中に状態を変えないようにした。
- 道路網全体（3364区間）の線は、表示モードと道路版が変わったときだけ作り直す。選択・登録・経路・目的地は差分の層だけを入れ替える。
- 通行不可区間の集合（`blocked`）は、報告の変更時だけ再計算する。以前は参照するたびに作り直していた。
- 状態の通知アラートは最前面の画面に出す。ルートからアラートを出すと、開いている設定やDeveloperModeのシートが閉じていたため。
