# 避難ナビ — Junction 2026 MVP

北九州市の小倉駅周辺と九工大前駅・九州工業大学戸畑キャンパス周辺の保存済みOSM歩行・道路ネットワーク、MapKit、通行不可報告、端末内経路検索、Core Location、音声、VIDVIPを接続した実験アプリです。同行者のいる管理された環境で評価します。安全性・施設入口・通行可能性を保証しません。

アプリアイコンは `App/Assets.xcassets/AppIcon.appiconset/AppIcon.png` に配置。提供されたデザインの外側の白い余白を除き、背景を正方形の四辺まで広げた画像を使用する。Xcodeの `AppIcon` アセットとしてビルドする。

## このPCで実行

1. `JunctionGuide.xcodeproj`をXcodeで開く。
2. Schemeは **JunctionGuide**。実行先は接続済みのiPhone（検証はiPhone 16 / iOS 27.0）または **iPhone 17 / iOS 27.0 Simulator**。
3. Xcode > Settings > AccountsにApple Accountを登録する。現在のPCには開発署名があり、アプリの実機ビルド・インストール・起動を確認した。
4. 署名情報はGit対象外の `Config/Local.xcconfig` に置く。`Config/Local.xcconfig.example` をコピーし、`JG_TEAM`（Team ID）と `JG_BUNDLE_ID`（Bundle Identifier）を自分の値にする。ファイルがない場合は `com.example.JunctionGuide`・Team未設定でビルドされる（シミュレーター用）。
5. Bundle Identifierを変えると実機では別アプリとして扱われ、保存済みの報告は引き継がれない。既存の別アプリを上書きする識別子は選ばない。
6. iPhoneをケーブル接続し、端末の「このコンピュータを信頼」を確認する。端末をロック解除した状態にする。
7. iOS設定 > プライバシーとセキュリティ > デベロッパモードを有効にする。今回の端末では有効化済み。
8. XcodeでRun（⌘R）。初回の開発者信頼が求められた場合は端末の設定から確認する。
9. 初回チュートリアルで通知・位置情報・カメラの許可を説明し、それぞれ確認する。後で設定も選べる。通知の許可とアプリ内の音声通知は別で、災害情報のプッシュ配信は実装していない。設定からチュートリアルを再確認できる。
10. シミュレーターでは実カメラ評価を行わない。目的地・区間一覧・経路の表示やDeveloperModeの模擬機能を使用する。

CLI:

```sh
cd <リポジトリのパス>
swift test
xcodebuild -project JunctionGuide.xcodeproj -scheme JunctionGuide \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -derivedDataPath Build/Simulator CODE_SIGNING_ALLOWED=NO build
xcodebuild -project JunctionGuide.xcodeproj -scheme JunctionGuide \
  -destination 'platform=iOS,id=<接続した端末のUDID>' \
  -derivedDataPath Build/Device -allowProvisioningUpdates build
```

## モデル配置

指定モデルをこのPCでCore MLコンパイルし、ローカルの `App/Models/vidvipo_yolov8n_2023-05-19.mlmodelc` を同梱しています。モデルの原本・コンパイル済みファイルはGitの対象外です。モデル取得・条件の入力画面はありません。

ローカル環境を作り直す場合:

```sh
Scripts/install_model.sh <保存先>/vidvipo_yolov8n_2023-05-19.mlmodel
```

モデルがない環境では `python3 Scripts/create_project.py` でモデル参照のないプロジェクトを生成でき、道路機能はビルドできます。生成スクリプトはプロジェクトと共有Schemeを再生成するため、Xcodeで独自に変更した設定がある場合は先に差分を確認してください。

[モデル・利用条件の記録](Docs/MODEL.md)を参照。今後の公開・第三者への配布はこの実験の実施と分けて判断します。

## 操作

- 起動後のホームは全画面の地図。上部に浮いた「目的地を入力」に施設名・住所を直接入力する。検索欄の下に保存済み地点のチップ、右下に通行不可登録・全面カメラ・現在位置の丸ボタン、下部に避難先と経路のパネルがある。入力中の候補を選ぶか、キーボードの検索で結果を表示する。検索欄の右端の丸×は、入力があれば消去し、空なら検索を閉じる。座標は「緯度, 経度」で直接入力も可能。地図の長押し、保存済み一覧からも任意の地点を選べる。名称検索と補完候補にはAppleの検索サービスへの通信が必要。
- 保存済みの小倉または戸畑ネットワーク外の地点も選択・表示できるが、通行不可除外を伴う経路案内は選択中の対応地域内だけ。現在地が別の対応地域に入ると道路網を自動で切り替え、設定から手動選択もできる。小倉と戸畑をまたぐ経路は作らない。ネットワーク内でも40m以内の道路接続点候補を利用者が確認する。候補がない場合や未確認のまま、経路を作らない。直線で施設入口への歩行接続を捏造しない。
- 「通行不可を避ける経路を確認」→「ナビ開始」または「カメラ案内」。施設入口・受入状況・経路を同行者と確認してから開始する。
  - ナビは進行方向が上の地図に、次の分岐バナー（距離・方向）、徒歩目安、残り距離を表示する。
  - カメラ案内は全面カメラに分岐バナーとAR方向矢印を重ね、カメラと候補通知を開始する。
  - 案内中は下部のボタンでナビとカメラを切り替えられる。
- AR方向矢印は、方位と現在位置から次の経路点への角度を示す概算のHUD表示。世界座標には固定しない。方位の精度が低い場合や道路照合が保留中の場合は矢印を出さない。徒歩目安は毎分60mで計算した目安。
- 「全面カメラで案内」から認識だけを開始することもできる。大きい文字では操作パネルをスクロールする。
- 現地外で模擬位置を使う場合はDeveloperMode内で有効にする。模擬位置を実位置とは扱わない。
- 通行不可登録は地図が初期表示。選択できる道路（3364区間）を青緑の線で表示する。道路を直接タップすると道路形状全体が赤く選択され、同じ道路への再タップで解除する。ドラッグは地図移動、ピンチは拡大縮小。複数候補は対象を確認して確定する。離れた道路は同時選択しない。
- VoiceOver用の区間一覧は補助ボタンから開く。なぞりによる複数区間の選択は詳細操作に残し、有効時は地図移動を停止する。
- 部分をなぞっても区間全体を赤く表示・登録・除外する。候補、両端、距離を確認して保存する。
- 報告はこの端末だけの地域別JSON。既存の`real-reports.json`は小倉用として引き継ぎ、戸畑は`real-reports-tobata-ground-osm.json`へ分ける。古い報告は自動解除しない。解除は設定から対象を確認して行う。
- 案内中は再読み上げ・停止・報告・カメラへ切り替えられる。アプリが背景へ移ったら位置・経路案内・カメラを停止する。
- 設定最下部「バージョン情報」を各間隔3秒以内で7回操作するとアプリ内DeveloperModeが開く。VoiceOverのボタン操作でも同じ条件。iOS設定のデベロッパモードとは別。
- 模擬位置と模擬報告は実報告と別ファイル。全閉鎖とリセットは模擬領域だけ。DeveloperModeを終了すると模擬動作・エラー注入・待機音声を停止する。
- 計測ログはメモリ内で直近2000イベントを保持し、DeveloperModeの明示操作で書き出す。画像・位置履歴・なぞり軌跡を含めない。保持上限による破棄数を表示する。
- DeveloperModeの統合デバッグログは、カテゴリ・レベル・文字列で検索でき、各行を展開すると詳細と発生元を表示する。DEBUGビルドでは直近500件を再起動後も保持し、Releaseでは保存しない。座標は記録しない。
- DeveloperModeには、状態ダッシュボード、学習モデルのBBOX表示のオン／オフ（クラス名・信頼度・表示閾値）、AR矢印のオン／オフ、方位補正、模擬方位、経路に沿った模擬歩行がある。
- 道路データを更新して報告の版が一致しない場合は案内を保留する。設定から「同じ区間IDの報告だけ引き継ぐ」または「旧報告を退避」を選べる。元ファイルは削除しない。

## よくある問題

| 問題 | 対応 |
|---|---|
| No profiles / Team未設定 | AccountsとTeamを確認。CLIでは`-allowProvisioningUpdates`。有料契約を自動で行わない |
| Lockedで起動不可 | 接続したまま端末をロック解除してRun |
| 無料プロファイルのアプリ数上限 | 本端末では実機UIテスト用Runnerの追加が上限に到達。既存アプリは削除していない。アプリ自体はインストール可能。実機UIテストはユーザーがインストール枠を確保してから実行 |
| カメラ権限拒否 | iOS設定でこのアプリのカメラ権限を変更。道路機能は独立して動作 |
| モデル未導入 | ローカル配置・Core MLコンパイル・プロジェクト再生成・再ビルドを確認 |
| 候補が複数／精度不足 | 方向・到着を保留。位置を新しく取得し、同行者と確認。GPSだけで歩道や高架を確定しない |
| 報告読込失敗／版不一致 | 案内を開始しない。0.4の道路データ更新後は設定の「道路データ更新後の報告」から引き継ぎか退避を選ぶ（元ファイルは退避として残る）。無断削除をしない |
| 地図通信なし | 一覧・保存済みネットワーク・検索を利用。MapKitのキャッシュを前提にしない |
| SDKとOSの組み合わせ | このPCではXcode 26.3 / SDK 26.2からiOS 27.0へのビルド・インストール・起動に成功。別環境での互換性は未確認 |

## 構成と検証

`Core/` は座標・ネットワーク、照合、Dijkstra（隣接表とヒープ）、案内の進捗・分岐、位置判定、報告保存と明示的な移行、デバッグログのモデル、通知抑制、音声待機管理。`App/` はSwiftUI、MapKit、端末権限・方位、カメラとBBOX・AR表示、共通音声、デバッグログ画面。第三者SDKは使用していません。

App/ の主なファイル:

| ファイル | 内容 |
|---|---|
| `JunctionGuideApp.swift` | 起動、チュートリアル分岐、状態通知 |
| `AppStore.swift` / `AppStore+Reports.swift` / `AppStore+Developer.swift` | 状態・経路案内 / 通行不可報告と移行 / DeveloperMode |
| `HomeScreen.swift` / `PlaceCard.swift` / `DestinationSearch.swift` | 全画面地図のホーム / 施設カード / 目的地検索 |
| `NavigationScreen.swift` / `CameraGuidance.swift` | 地図ナビ / 全面カメラ案内・AR矢印・BBOX |
| `ReportScreen.swift` / `SettingsScreen.swift` / `DeveloperScreen.swift` / `DebugLogger.swift` | 通行不可登録 / 設定 / DeveloperMode / デバッグログ |
| `MapView.swift` / `Services.swift` / `Camera.swift` / `Permissions.swift` / `AppFiles.swift` | MapKit / 位置・方位・音声 / カメラ・推論 / 権限 / 保存先 |

情報の取り扱い:

- 報告・デバッグログ・書き出しファイルは端末のファイル保護（初回ロック解除まで暗号化）付きで保存する。
- デバッグログには座標・位置履歴・画像・なぞり軌跡のほか、検索語・施設名・読み上げ文も記録しない（文字数などの件数だけ）。
- コンソール出力（`GUIDE_*`）はDEBUGビルドのみ。
- UIテストは起動引数 `--ui-testing` で一時ディレクトリを使い、実際の報告を読み書きしない（DEBUGビルドのみ有効）。
- プライバシーマニフェスト（`App/PrivacyInfo.xcprivacy`）：トラッキングなし、収集データなし。UserDefaults（CA92.1）と経過時間計測（35F9.1）の利用理由を記載。
- 個人のパス・端末ID・Team IDはリポジトリに置かない（署名は `Config/Local.xcconfig`）。
