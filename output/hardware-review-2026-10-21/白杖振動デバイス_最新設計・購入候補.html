iPhoneで上半身・頭部の高さの障害物を検知 → BLE → 白杖のグリップで振動。スマホは首掛けにし、背面カメラを前へ向ける。白杖は110cm、黒いグリップ。

01　白杖側の機構をすべて交換グリップ内へ

300mAhの保護回路付きLiPo、XIAO nRF52840、3V電源・FET、振動モーターと配線を、黒い交換グリップ内に収納する。BLEと充電回路・アンテナを1枚にまとめ、乾電池ホルダー・5V昇降圧基板・外付けアンテナを省く。元の金属管と折りたたみゴムはそのまま残す。

新しい収納目標は外径38mm・長さ130mm。前案42×200mmに対し、長さ35%減、円柱の外形容積で約47%減の設計目標。シャフト径14mm、管を囲う通路径16mm、偏心8mm、電池室22×8mmを仮定し、電池と基板は長さ方向に分ける。

軸方向は固定具20＋モーター10＋回路35＋電池/配線55＋ふた等10＝130mm。電池本体は37mmでも、リード約100mm・PH端子・曲げ・点検余白まで必要。資料の完成品厚さ5.2mmと販売店5.6mmが異なるため、厚さ5.6mm以上を収納検討値とする。満充電時・経年の正常最大寸法は要確認。

白杖は未入手。これは製作図・適合保証ではない。元のゴムの結び目・固定具・ストラップと第1継ぎ目を避け、上端を延長せず全長110cmを維持できることが成立条件。電池・ネジ・配線は管内に入れない。

02　充電式の電源と回路

3.7V・300mAhの1セルLiPoを第一候補に変更。XIAO nRF52840のUSB-C充電を利用し、別体の充電基板と5V昇圧回路は使わない。旧ESP32C3案は旧版として保持する。

接続元接続先・条件（機能接続案・未実装）

保護と未使用素子1S4の帯側 → モーター＋、反対側 → モーター－。未使用FETはG2（5番）・S2（4番）をGND、D2（3番）を未接続。全GNDを共通化。

モーターは3V・50mA、内部IC付きで極性あり。満充電4.2Vを直接加えず、HIGH/LOWの時間パターンで制御する。高周波PWM・逆回転駆動を流用しない。LDOの損失は満充電時(4.2−3.0)×0.05＝約0.06W＋内部消費。低電圧時は3Vを維持できないため、電圧低下時に通知して停止する仕様を追加する。

電池仕様：標準充電60mA、改訂2023年資料の最大連続充電150mA、最大連続放電300mA、充電上限4.2V、放電下限3.0V、充電温度0〜45℃。販売店PDFの旧充電上限300mAは採用せず、新しい150mAを用いる。50mA設定で電圧・電流・温度・充電終了を実測する。

充電中は振動OFF、FWもUSB検出時にBLE/振動処理を止めて負荷を抑える。充電ICのTSは公開回路図で固定抵抗のため、電池温度の自動監視があるとは扱わない。初期試作は点検ふたを開け、電池温度を監視できる卓上充電のみ。セル温度監視付きの閉ケース充電は別途設計が必要。完全遮断はUSBを外しPHコネクターを抜く。

50mAなら300÷50＝6時間に定電圧充電時間が加わる。実際の満充電時間と終止電流の適合は未確認。小型化を優先した暫定案であり、量産用の確定回路ではない。

Command 10バイト：version[1] / state[1] / sequence[2] / TTL[2] / distance_mm[2] / flags[1] / reserved[1]。複数バイトはLittle Endian。version=1、TTL=1000ms、未知距離=65535、予約ビット=0。例：01 02 01 00 E8 03 DC 05 00 00。

stateは0=CLEAR / 1=CAUTION / 2=DANGER / 3=UNAVAILABLE。flagsはbit0=床面、bit1=手動、他は0。sequenceは16bit周回、差分1〜32767を新規として受理。危険判定は有効な連続2フレームで確定、無効化は即時とする。

250msごとに最新状態を送る。600ms以上古い深度や無効姿勢、背景移行、カメラ停止はUNAVAILABLE。受理後1000ms更新がなければ危険振動を止める。D1（P0.03）のLOWを初期値とし、同じ状態の再送では振動位相をリセットしない。

状態振動案
CLEAR停止
CAUTION150ms ON / 850ms OFF
DANGER200ms ON / 150ms OFF
UNAVAILABLE危険パターンを停止。遷移時だけ50ms ON / 100ms OFFを3回の案。起動時は鳴らさない。

Statusも10バイト。version / applied_state / error_flags / gpio_level / last_sequence[2] / uptime_ms[4]。GPIO状態は実際の振動を検出した証拠ではない。電池残量は未対応。基板の電圧計測を用いる低電圧停止・復帰条件はv0.2として設計/試験し、残量%を断定しない。距離閾値・連続判定・認証方式は共有元の未決定事項を整理してから固定する。

膨らみ・変形・異臭・異常発熱があれば使用/充電を止めて交換する。余白は製造差・正常変化・取り出しのためであり、異常膨張した電池を使い続けるための空間ではない。完成品最大寸法と満充電/経年変化を確認できるまで筐体寸法を確定しない。

06　先行実装をどう参考にするか

一次資料と公開ソースを2026年10月21日に確認。以下は参考事例であり、今回の110cm白杖への収納や電池持ちを保証するものではない。

事例・サイト確認した内容今回に取り入れる点
BlindMaps：PrototypesBLEでグリップ・スマホ・ビーコンを接続。交換式グリップを3Dプリント。iPhone方向振動の試験写真も掲載。検知処理はスマホ、白杖側は小さなBLE受信・振動装置という構成と、交換グリップの試作方法。リアルタイム触覚連携の一部は次段階と記載。
Shepherd：公開リポジトリーiPhone側の処理とESP32側BLE/触覚処理、CAD資料を公開。現行FWは12バイト受信、距離で振動間隔を変更。処理をスマホに集約し、受信と振動処理を分ける考え方を参考にする。車輪・操舵・Taptic駆動は採用しない。
SmartCane：公式概要白杖の上部/握り部に装着。超音波検知、距離別振動、内蔵充電池を使用。電池・回路を手元に集める構成と、握り位置が変わっても振動を伝える評価項目。検知は超音波であり今回のiPhone方式とは異なる。

公開コードを確認して調整する点

確認したSmartCane_ESP32.inoでは、受信は12バイトだがBLE_PROTOCOL.mdは1バイトと説明している。250ms期限切れ判定は操舵入力側にあり、tapticTaskは接続・鮮度を見ず保存距離で振動を続ける。今回は既存10バイト仕様を維持し、切断・TTL切れ・無効検知で危険振動を停止させる。内蔵ICモーターにTapticの波形も流用しない。
